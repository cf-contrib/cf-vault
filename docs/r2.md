# R2

R2 speaks the S3 API, so tools such as Terraform's S3 backend need an access key, a secret and a
session token. cf-vault delivers them as `CLOUDFLARE_R2_*` variables.

## When can you have R2 credentials?

| Profile | Where the credentials come from | What it needs |
|---|---|---|
| `oauth2` with `exchange` | the **broker**: the broker profile has a `bucket` | a broker profile with a bucket; `[p.r2]` is not allowed here |
| `api_token` with `[p.r2]` | **derived from the stored API token** | a token with an R2 permission (Workers R2 Storage Write works) |
| `oauth2` **without** `exchange`, with `[p.r2]`, signed in with **Cloudflare's own OAuth** | cf-vault **mints a short-lived account token** as the parent, derives the credentials, and deletes the token | the sign-in's scopes `account-api-tokens.write` and `workers-r2.write` (`workers-r2.read` for read-only) |
| `oauth2` without `exchange`, with `[p.r2]`, signed in with **another provider** (for example Access) | the same attempt, but Cloudflare does not accept that provider's token, so it fails | not usable: use `exchange`, or an `api_token` profile |
| any profile with a token supplied in `CLOUDFLARE_API_TOKEN` (CI) | as its type says: `api_token` derives from it, `oauth2` mints with it | the same permissions |
| a profile with no `[p.r2]` and no broker bucket | none: no R2 variables are set and no R2 request is made | |

One profile, one bucket: use a second profile for a second bucket.

## From a broker

A broker profile with a `bucket` returns temporary credentials for it, limited to the key prefixes
the broker fills in. cf-vault delivers them with the API token, if the profile has one. See
[Broker](broker.md).

## From an API token

```toml
[ci-state]
type = "api_token"
account_id = "abc123"

[ci-state.r2]
bucket = "org-terraform-state"          # exactly one; use one profile per bucket
permission = "object-read-write"        # or "object-read-only"
prefixes = ["github.com/example-org/app/"]
```

The token needs an R2 permission (Workers R2 Storage Write is known to work); without one,
Cloudflare answers with error `10000` and cf-vault says so.

## From Cloudflare's own OAuth

```toml
[personal]
type = "oauth2"
account_id = "abc123"

[personal.oauth2]
issuer = "https://dash.cloudflare.com"
client_id = "<your client id>"
scopes = ["offline_access", "account-api-tokens.write", "workers-r2.write"]

[personal.r2]
bucket = "org-terraform-state"
prefixes = ["github.com/example-org/app/"]
```

`exec` then creates an account API token with only the R2 permission the credentials need
(`workers-r2.write`, or `workers-r2.read` for `object-read-only`) and an expiry a few minutes past
the credentials' lifetime, derives the credentials from it, and deletes the token again, whatever
happened. A brand-new token is refused for a moment, so cf-vault retries for a few seconds. If the
token cannot be deleted, cf-vault warns and it expires by itself. `account-api-tokens.write` is a
sensitive scope: switch it on at the consent screen (see [Cloudflare OAuth](cloudflare-oauth.md)).
The command receives the session's access token as `CLOUDFLARE_API_TOKEN` and the R2 variables; it
never sees the parent token.

## Lifetime

The credentials last **15 minutes** unless `--ttl` is given, and **cannot be revoked early**: keep
them short. A profile with no `r2` table makes no R2 request.

## What the command gets

| Variable | Value |
|---|---|
| `CLOUDFLARE_R2_ACCESS_KEY_ID`, `CLOUDFLARE_R2_SECRET_ACCESS_KEY`, `CLOUDFLARE_R2_SESSION_TOKEN` | the temporary credentials |
| `CLOUDFLARE_R2_ENDPOINT` | `https://<account id>.r2.cloudflarestorage.com` (or the broker's) |
| `CLOUDFLARE_R2_BUCKET` | the bucket |

cf-vault never sets or changes `AWS_*`. S3 tools read those, so map them for the one command that
needs them, or use a `credential_process` helper.

## Terraform's S3 backend

Point the backend at an AWS profile whose `credential_process` prints the credentials from
`CLOUDFLARE_R2_*`, such as
[`terraform-cloudflare-backend`](https://github.com/tf-contrib/terraform-cloudflare-backend), and run
Terraform under cf-vault:

```bash
cf-vault exec -p production --ttl 30m -- tofu plan
```

The helper does not pass the expiry on, so a run longer than the credentials' lifetime can fail to
save state: use `--ttl` for long applies.
